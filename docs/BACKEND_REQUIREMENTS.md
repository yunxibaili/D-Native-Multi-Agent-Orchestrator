# 后端需求 — LAYA 本机多 Agent 编排

更新日期：2026-10-13
状态：用户确认的需求方向；本文不代表全部已实现或授权开始实现。
范围：后端能力与对外契约。前端需求尚未讨论，进入前端阶段前必须提醒用户单独确认。

**唯一当前状态基准：[PROJECT_BASELINE.md](PROJECT_BASELINE.md)。** 本文保存需求目标，
不另设封板/授权表；实现切片与下一任务顺序见 [STAGE_ANALYSIS.md](STAGE_ANALYSIS.md)。
这是个人工作台项目，先交付最小可用闭环；复用当前内核，不以企业级设计或非阻断 P2 拖住全部推进。

## 1. 产品目标

用户提交目标后，系统组织本机已安装、已授权的多个 Native Agent 协作。
LAYA（laya）按任务选择工作流、具体 Agent 和模型、所需 Skill 以及 MCP 工具；
既有调度和执行系统在预算、权限、隔离和生命周期约束内落实执行。
优先使用满足任务要求的免费资源，发生不可用或额度耗尽时安全接力，
最终交付代码、报告、真实测试和可核查证据。

LAYA 是结构化任务级决策者；Agent 负责生成候选方案和具体内容。
候选方案生成者没有自主调度、任务认领或绕过准入的权力。

## 2. 输入与执行边界（REQ-01）

后端接收目标、项目目录、验收标准、技术约束、允许操作和数据发送范围。
支持执行时间、最大并发、最大返工次数、最大接力次数及费用限制。
信息足够时自动推进；缺失信息影响正确性、范围或费用时才请求补充。

一次授权对应一个有终点的工作流。内部步骤可以自动推进，但不能无限返工、
自行扩大范围或跨越最终 Human Gate。现有 Round 之后自动动作仍为 NONE；
跨 Round 自动推进属于后续明确设计和授权范围。

## 3. Agent 与模型发现（REQ-02）

复用现有 discover、doctor、AdapterRegistry 和 ModelRegistry，优先读取官方接口。

- 区分未发现、已安装、未连接、认证异常、配置异常、实际可调用和能力不足。
- 枚举 Agent 已配置入口中的模型，保留完整模型标识、来源、版本和更新时间。
- 区分目录列出、账户已连接、实际调用验证通过；列出不等于有权限或有额度。
- 记录显式选模型、会话恢复、工具、Skill、MCP、并发及工作区隔离能力。
- 无法自动枚举时允许手动配置，并标记未验证；不兼容任意未知 Agent。
- 不读取、展示、复制凭据内容；账户归属使用非敏感标识和既有授权状态。
- 不自动安装 Agent 或代替用户登录。

Agent 软件可以支持许多模型；不保证所有 Agent 支持同一套模型。

## 4. 用户模型选择（REQ-03）

| 方式 | 约束 |
|---|---|
| 自动 | LAYA 在用户允许的候选中选择 |
| 偏好 | 优先指定组合，允许按预设规则替换 |
| 固定 | 锁定 Agent 与模型，不允许 LAYA 自行替换 |

选择可作用于项目默认、角色默认和具体任务；具体任务覆盖角色，角色覆盖项目。
固定选择不可用时等待或暂停并说明原因。用户固定付费模型不自动构成付费授权。
执行中的修改通过明确接力生效；未开始任务允许重新选择。
支持时可配置推理档位，参数能力必须由适配器确认，不能向所有模型强加同一参数。

## 5. 分配对象与多会话（REQ-04）

LAYA 选择具体 Agent × Model 和允许的调用入口，并表达新建或继续会话的意图。
SessionRegistry 创建、解析和校验真实会话；LAYA 不编造 native thread ID。
WorkerIdentity 继续复用 taskId、agentId、modelId、sessionId，入口和账户归属作为候选事实，
不新增 WorkerManager 或第二套身份存储。

同一 Agent 可以通过多个独立会话同时运行不同模型，也可以运行同模型的独立任务。
每个 Worker 的任务、上下文、日志、进程生命周期和取消必须独立。
不通过修改 Agent 全局默认模型实现并发选模型；优先使用逐请求/逐会话参数。

“多开”是独立执行会话，是否打开原生 GUI 窗口由未来前端需求和 Agent 接口决定。
按整机、Agent、模型入口和共享额度范围施加必要并发约束。
不能证明并发隔离的组合限制为顺序执行，不因接口存在就宣称实际隔离。
写任务使用独立工作区，集成操作受控；当前 PARALLEL_WRITE 仍为 CLOSED。

## 6. 模型能力与 LAYA 选择（REQ-05）

能力评估对象是实际 Agent＋模型＋配置＋工具环境的组合，不只看模型品牌。
能力信息来自官方材料、相关公开评测和本项目真实表现，保留来源、样本范围和时间；
未验证即未知，不能把模型自述或一次成功提升为通用能力结论。

| 角色/任务 | 优先考察的能力 |
|---|---|
| 调研与方案 | 搜索工具、来源核查、长材料理解、结论与限制 |
| 前端实现 | 框架、交互、样式、相关工具；需要时的图片理解 |
| 后端实现 | 相关语言、接口、数据、错误处理和变更正确性 |
| 测试 | 边界条件、有效用例、实际运行与失败定位 |
| 排错与重构 | 跨文件理解、持续工具使用、回归风险 |
| 独立审核 | 真实问题发现、证据核查、误报控制 |
| 简单整理 | 稳定性、速度和低消耗 |

先检查用户约束和必要能力，再过滤权限、数据政策、费用与可用性，
最后由 LAYA 根据任务、历史表现、额度和负载选择合格候选。
不永久绑定“某模型只能做前端”，不为节省单次费用无限使用持续失败的模型。
起步复用少量能力标签与既有执行记录，不先建设大型排行榜或训练平台。
LAYA 置信度不能覆盖费用、权限或能力硬约束；应以代表性任务验证决策效果。

## 7. Skill 与 MCP 决策（REQ-06）

LAYA 不仅分配 Agent 和模型，还必须选择任务需要的 Skill 与 MCP Server 中的具体工具。
能力选择是任务级决策的一部分，不建立第二个工具选择大脑。

- 能力发现：按 Agent/入口记录实际支持、已连接、已授权的 Skill 和 MCP 工具。
- 用户控制：允许指定、偏好、禁用或锁定 Skill、MCP Server 和具体工具。
- 选择结果：明确 Skill 标识/版本，MCP Server 与工具标识，以及选择用途和依据。
- 按需加载：只提供当前任务必要的技能说明、工具定义和上下文，不广播全部目录。
- 工具优先：搜索、文件片段、状态、测试等确定性事实优先由明确工具取得。
- 节点调整：任务开始、阶段变化、能力失效或受阻时，LAYA 可重新选择能力集合；
  不要求每个细小调用都额外经过一次 LAYA，以免增加延迟和 token。
- 执行归属：Agent 或既有工具执行通道负责实际调用；参数、权限和副作用仍需校验。
- 缓存复用：按任务、权限、数据范围和有效期复用结果，保留原始证据引用。
- 降级：缺少工具或 Skill 时标明能力不足；不假装加载成功或静默改用未授权服务。
- 可观测：分开记录请求的能力、实际加载/调用的能力、结果和失败原因。

原生 Agent 不支持逐任务限制工具时，不能仅靠提示词宣称强制限制已生效；
应限制候选、采用明确验证的配置方式，或报告当前不能满足该任务的约束。
首版优先复用 Agent 自带 Skill/MCP 接口，不重建通用 Agent Runtime 或全面拦截其内部调用。
发现第三方 Skill/MCP 时同时检查来源、许可、维护、Windows 可用性和数据权限。

## 8. 异构任务与工作流（REQ-07）

Agent 生成结构化候选任务，LAYA 选择/调整；既有 Planner 校验 DAG 并提交 TaskStore。
每个任务包含角色、具体目标、依赖、输入材料、验收标准、所需能力和允许写入范围。

典型软件开发流程：
需求理解/必要调研 → 方案与接口约定 → 前端/后端/测试设计 → 集成测试 → 独立审核 → 有限返工或交付。

有依赖则顺序执行，无冲突且准入允许才并行。测试设计可提前，集成测试等待实现。
小任务减少角色；资源不足可以顺序完成。不强制四个 Agent，不默认多人重复实现同一代码。
角色与 Agent 软件解耦，同一 Agent 的不同模型/会话可以承担不同角色。
审核与开发执行上下文分离，保持现有独立审核职责和统一 Verification 入口。

## 9. 免费优先与额度（REQ-08）

默认产品模式是“不新增付费支出”；这是待实现的端到端要求，
不代表当前所有 CLI 路径已经默认执行严格免费策略。

区分官方免费、赠送额度、订阅包含额度、按量付费、费用未知。
免费资格属于实际调用入口和账户，不能只看模型名、国别或单次 cost=0。
记录依据、观察时间、失效时间、已知剩余额度及重置时间。
多个模型/会话共享账户额度时统一考虑，不能重复计算成多份余额。

额度未知与费用未知分别处理：免费依据可靠但数量不可查询时，按明确策略尝试；
费用未知不进入严格免费模式。不能将所有 unknown 状态统一视为可用，
必须兼容现有 Spawn Gate 对观测失败和未连接的拒绝语义。

每次分配和接力重新校验费用及数据政策。
覆盖开发、调研、审核、辅助模型和收费工具；不能只限制主模型。
所有免费候选不可用时等待或暂停。付费必须有预先授权和预算上限；
外部 Agent 的隐藏辅助调用或自动充值无法核实时，不能承诺严格零新增费用。

## 10. 自动接力（REQ-09）

区分额度耗尽、临时限流、认证失败、服务异常与任务失败，保留真实原因。
临时限流遵守可获得的 Retry-After 等提示，不把所有 429 视为额度耗尽。

LAYA 可以选择同 Agent 的其他模型、其他 Agent 的相同模型或其他合格模型。
结合能力、费用、上下文迁移成本和负载决定，不固定切换顺序。
同 Task，新 Attempt、新 Lease；模型变化建立符合现有契约的新 Session/Worker。
先确认旧执行停止或不能再写入，再允许接手；不保留两个有效写入者。
交接目标、已完成内容、代码变更、测试、报告、工作区和剩余工作。
跨 Agent 不承诺原生会话或隐藏推理完整迁移；用户不必手工重新复制需求。
固定选择和用户排除规则在接力时仍然有效，并限制切换和返工次数。

### 10.1 执行中模型中断（后续边界收口项，尚未实现验收）

用户补充：任务执行途中可能出现模型掉线、服务中断或额度用完；纳入后续边界情况统一实现与验证，
不要求本轮用户选择功能提前完成整套恢复机制。

- 区分网络/流中断、临时限流、额度耗尽、认证失效、服务错误、Agent 崩溃与原因未知。
  一段时间无输出不等于模型死亡；保留真实错误与最后活动时间，遵循既有 deadline/取消契约。
- 对临时故障按可用提示进行有界等待/重试，受任务总时限、重试次数和预算约束；
  重试可能再次执行工具或写文件，不能盲目重放整个任务，也不能无限重试或循环切换模型。
- 需要接力时，由既有 LAYA/assignment/handoff 路径选择允许的 Agent × Model，
  先确认旧执行停止或可靠失去写入能力；停止无法确认时保留保护并报告受阻，不启动第二个写入者。
- 保留已完成文件、报告、测试证据与明确的剩余工作，区分部分完成与通过验收；
  不自动删除或回滚用户改动，不承诺跨模型恢复原生隐藏上下文。
- 自动选择可在合格候选间接力；固定选择继续保持固定，不能继续时等待用户处理，
  不擅自替换或转付费；无合格免费候选时明确受阻。
- 对外给出中断原因（未知则标未知）、当前停止确认状态、已保留成果、重试/接力记录和待处理事项。

后续用受控 fixture 覆盖：流中途断开、持续无输出但进程仍活着、429/额度/认证错误、
旧执行停止未确认、部分写入后的重试、固定模型失效、无替代候选，以及接力后再次失败的有界停止。
这些是待验收用例，不代表当前已完成自动恢复。

## 11. 上下文与节省消耗（REQ-10）

按需读取相关文件和差异，长日志提供摘要及原始引用。
复用调研、接口约定、工具结果、Agent 自带上下文管理和已安装能力。
调研报告包含来源、时间、适用条件和不确定性。
区分 Agent 声称完成、系统实际观察与审核结论。
保留现有 memory 的来源和不可信输入边界，不把历史记忆作为指令或任务状态。

记录总 token（含调研/规划/审核/接力）、额外调用、耗时、返工、费用和完成质量。
供应商不报告的部分标记未知，不能计作零；本地 LAYA 无 API 费用不代表无计算成本。
通过相近任务、相同验收标准比较效果，不预先承诺固定节省比例。

## 12. 对外状态与结果（REQ-11）

后端输出任务依赖、角色、请求与实际 Agent/Model/Session/Skill/工具、
进度、阻塞原因、额度事实、接力历史、交付物和验证结果。
只记录适配器确实能观察的事实；实际模型无法核对时标为未验证。
取消与停止后续调度、从检查点继续、调整未开始任务应有明确语义。
暂停不等于任意进程可原地冻结恢复；需要区分停止调度、协作检查点和取消。
具体界面布局、窗口形态和交互留待前端需求阶段讨论。

最终交付包含变更、报告、真实测试、审核结论和剩余问题。
发布、推送、超预算、扩大范围遵循用户已有授权，不由 LAYA 绕过。

## 13. 首版范围与非目标（REQ-12）

首版以软件开发闭环为目标。安全审计/渗透测试工作流以后单独确认：
只在授权目标、范围、允许操作和影响限制内分配任务。
首版复用 Agent-native 调用，不自动引入 provider-api、gateway 或新凭据系统。

暂不建设任意 Agent 自动兼容、Skill 市场、通用工作流市场、全内部工具拦截、
无限自主返工、大规模 LAYA 微调或共享目录自由并行写入。
复用顺序：项目现有实现 → 系统能力 → 已安装依赖 → 成熟开源 → 最小自研。

## 14. 验收要求

| 编号 | 必须给出的证据 |
|---|---|
| AC-01 | 发现一个支持的 Agent，并区分其模型目录、连接和实际调用状态 |
| AC-02 | 自动、偏好、固定规则生效；不可用时不绕过固定选择 |
| AC-03 | LAYA 返回明确 Agent＋Model，并由既有准入链执行 |
| AC-04 | 同 Agent 不同模型独立会话并行；上下文、取消和工作区互不干扰 |
| AC-05 | LAYA 选择 Skill 和具体 MCP 工具，展示请求与实际加载/调用差异 |
| AC-06 | 受禁用、不可用或无法强制限制的工具不被误报为已安全启用 |
| AC-07 | 调研、前后端、测试形成不同任务，依赖和交付物被实际使用 |
| AC-08 | 资源耗尽及执行中模型中断安全处理；有界重试/接力、保留部分成果，旧执行不再写入，共享额度不重复计算 |
| AC-09 | 严格免费/预算/数据政策覆盖每次分配与接力；全部不可用不静默付费 |
| AC-10 | token、质量、费用和耗时有真实或明确未知的记录，可做同标准比较 |
| AC-11 | 真实测试与独立审核进入统一结果；不以 Agent 自述替代完成证据 |
| AC-12 | 有界执行到达终点停止；前端阶段开始前提醒用户确认前端需求 |

## 15. 调研依据与使用限制

以下资料在 2026-10-11 调查过，仅支持接口/方法判断，不构成本机验收：

- [OpenCode CLI](https://opencode.ai/docs/cli/#models)：模型枚举与指定。
- [OpenCode Models](https://opencode.ai/docs/models/)：模型标识和支持时的配置。
- [OpenCode Server](https://opencode.ai/docs/server/)：会话和模型请求接口。
- [OpenCode Zen](https://opencode.ai/docs/zen/)：免费期限与数据政策需要随入口核实。
- [LAYA](https://github.com/NandhaKishorM/laya)：结构化决策；公开新版本能力不等于本机已升级。
- [Terminal-Bench](https://www.tbench.ai/news/announcement)：评估 Agent/模型组合的方法。
- [Agent Orchestrator](https://github.com/OrchestratorInc/agent-orchestrator)：Apache-2.0，
  本机多 Agent/工作区协作的复用候选；未完成迁移验证，不决定替换当前内核。
- [RouteLLM](https://github.com/lm-sys/RouteLLM)：Apache-2.0，参考路由评估方法；
  不作为新增决策依赖，维护和本机兼容性未完成采用评估。
- [OpenRouter limits](https://openrouter.ai/docs/api_reference/limits)：说明限流与额度需分开识别；
  不表示项目已经接入 OpenRouter。

实现差距和阶段边界见 [阶段分析](STAGE_ANALYSIS.md)，当前事实见 [项目基线](PROJECT_BASELINE.md)。

计划输入契约：内置候选为有界 `full/lean`（顺序）与 `duo/trio`（协作）；需要适配具体项目时，用 opt-in 的
结构化计划文件（`--workflow-plan <file>`，JSON，`kind` 为 `sequential|collaborate`，含 role/taskType/可选
fileScope/deliverable/可选 dependencies 与协作的 integratorMember）替换内置候选。文件不命名 taskId/agent/model，
只描述有界候选；非法输入在写入前拒绝。完整 Skill/MCP 选择、角色计划与真实模型多模型兼容性按后续切片推进。
阶段确认契约（B4.3/B4.3a）：opt-in 的 `--stage <file>` 声明当前阶段材料（stageId/scope/requirement/acceptance，可选
planRef），`--confirm <digest>` 是用户对**该材料与实际计划**的确认——digest 覆盖材料字段、目标 objective、工作流模式与
有效计划内容（role/taskType/fileScope/deliverable/dependencies/集成责任）及 planRef，任一变化即使 plan id 不变也失效；
计划文件在确认处读取并冻结，`planRef` 必须命中有效计划 id 或计划文件本身。材料文件不得自我批准。材料缺失/未确认/
别阶段/自我批准/planRef 不匹配/材料超出可交付上限时，入口在任何外部调用与建任务前拒绝（不静默截断）。材料**完整嵌入**
任务验收条件/brief/验收材料，不依赖不可达的文件引用。完整需求/计划/阶段批准链仍属后续。
实现边界：以上确认绑定目前仅在显式 sequential/collaborate 工作流独立验证；--stage 与 legacy 的组合仍有实际计划未绑定 P1。
要求不放宽；最小建议在阶段门拒绝未支持组合，保留不带 --stage 的旧入口。当前状态以唯一基线为准。
提示词/规划不代表已经实现。
两层都复用既有 Planner / Assignment / Scheduler / SessionRegistry / WorkerIdentity / Fan-out
与 ResourceClaim / Workspace，**不新增拥有调度权的“主管 Agent”**，也不新增 TeamStore、WorkerManager、
第二套 DAG 或第二套任务状态机。

### 16.1 功能 A：跨角色独立任务分配（REQ-13）

用户提交目标后，LAYA 拆分工作流，为每项任务选择：**具体 Agent、Agent 内的具体模型、独立执行会话、
必要 Skill 与 MCP 工具**，以及输入材料、验收标准与交付物。
角色按任务变化，不固定四个 Agent；依赖关系决定顺序，具备条件才并行。
LAYA 作决策，既有 Planner / Assignment / Scheduler 落实执行。
每项任务必须落实到**具体 Agent × Model 与独立任务/会话**。

### 16.2 功能 B：同一目标的模型协作组（REQ-14）

某项任务可由 LAYA 分配给 **2–3 个模型**共同完成；成员可来自**同一 Agent 的不同模型/会话**，
也可来自**不同 Agent**。默认分工共建，每个成员仍有**独立子任务**：具体 Agent × Model、独立会话、
职责、依赖、文件范围、交付物与验收条件。LAYA 指定分工与**集成责任**；成员数量按需要决定。
**不默认全员重复实现、不广播全部上下文；不把多数票或“所有成员结束”直接当成验收通过。**

### 16.3 边界（与既有契约一致）

- 每个成员必须落实到具体 Agent × Model 与独立任务/会话；**同一个 taskId 不得被复制成多个同时执行的
  Worker**（既有 fan-out 用“父容器任务 + 独立 child task”满足该约束）。
- 费用服从用户允许池和授权策略，免费优先可作为偏好；自动/偏好/固定选择目标保留（见 REQ-03 / REQ-08）。
- Skill / MCP 由 LAYA 作**任务级**选择，按需加载（见 REQ-06）。
- **同任务协作组 ≠ 开放并行写**：`PARALLEL_WRITE=CLOSED`，写任务不得绕过既有准入并发执行；
  分工计划可以表达未来并行意图，但当前执行仍须遵守顺序、隔离与集成约束；
  **不得把 PARALLEL_READ 改名后用于写入**。
- “前端”只是任务编排示例；本产品前端设计/实现尚未开始。
- 不新增第二套 Runtime、Python 框架、群聊平台或 provider 网关。

## 17. 最小交付与分片原则

1. 先打通功能 A 的调研→实现→测试→既有独立审核，再推进功能 B 的 2–3 模型分工共建。
   同目标组不是简单群聊或投票，每成员必须有可识别的职责和实际下游消费的交付物。
2. 首个工作流切片允许顺序执行；并行意图不等于开放并行写。保持现有身份、资源、停止和验收约束。
3. LAYA 从当前合法候选选择计划与具体 Agent × Model；候选由用户、明确模板或已授权内容生成提供。
   不强制额外调用规划模型，不把 LAYA 的 typed choice 假称为任意自由文本任务生成。
4. 输入与交付使用既有 brief/handoff/evidence；只增加当前闭环缺失的字段，不建设新 TeamStore 或工作流引擎。
5. 角色默认、prefer、完整工具与费用事实、模型掉线恢复分片补齐。尚未实现的能力保持未知/拒绝，
   不能为先跑通而放宽真实准入，也不必阻塞受控 fixture 的工作流接线验证。
6. DSH 当前不支持逐请求模型；用户已配置的 API 入口不能被当成该协议已支持模型选择的证据。
   不自动改本机 API、Agent 默认模型或凭据；实际可用性按适配器能力与真实证据确定。

目标要求不缩水；某个最小切片 PASS 不表示所有 AC 已完成。阶段状态只在唯一基线维护。
